# 驿站闭环隔离验收

本流程只在 GitHub 托管临时 runner 或明确启动的本机测试环境运行。
不连接惠普电脑，不部署生产环境，不调用真实联盟、短信、支付或 Token 网关。

## 验收范围

- MySQL 8、Redis 和真实 Spring Boot HTTP 接口。
- 管理员和会员密码登录，拒绝未登录、错误密码、禁用会员。
- 邀请码绑定、重复绑定、竞争驿站、请求体会员编号伪造、跨租户拒绝。
- 专用模拟订单确认佣金 1 元，消费者 0.60 元、驿站 0.20 元，剩余 0.20 元作为平台未分配部分；并非真实经营定价。
- 通过现有管理接口触发结算任务，核对真实 MySQL 余额与资产流水；重复结算不重复记账。
- 通过现有退款接口冲回消费者和驿站收益；重复退款不新增资金流水。
- Playwright 使用真实登录表单，识别实际画出的二维码，验证访客邀请码登录后绑定；不伪造 HTTP 响应。
- 浏览器与应用容器均阻断第三方网络访问。

订单输入为 CI 专用合成的上游已结算事件，不等于联盟实单、供应商同步链路或真实付款验收。
二维码使用图像解码自动验证，不等于实体手机摄像头验收。

## 隔离约束

- 只能访问 127.0.0.1 的固定测试端口：网页 18081、后端 48081、MySQL 13307、Redis 16380。
- Docker 项目名含本次 run id，所有容器与数据卷归该项目；没有全局 container_name，也不使用已有数据卷。
- 内部 Docker 网络禁止容器访问外网。原有服务不加入此网络。
- 每次随机生成数据库、Redis 和测试账号密码；凭证不打印、不上传产物。
- 初始化生成数据库随机标记，夹具脚本核验标记后才允许写入。
- 测试容器关闭管理员图形验证码，但继续使用真实密码认证；安全 mock 始终关闭。
- 会员、装修及登录后使用的部分商城表在仓库初始化脚本中缺失，本流程根据当前实体建立测试专用夹具表；不修改生产初始化 SQL，不将测试数据当作正式数据库迁移。
- 测试完只清理本次独立项目，不使用 docker system prune 或全局清理。

## 真实数据库验收发现并修复的问题

同订单的消费者返利和驿站分佣共用返利记录表，原消费者查询缺少角色条件，MySQL 可能返回驿站记录，导致会员一致性校验拒绝结算。已先用真实 HTTP 复现，再增加 4 项数据库测试（其中 2 项在旧逻辑失败），将主返利查询限定为 SELF 或历史 NULL 角色。构建与验收必须使用修复后的新产物。

直接入账时，资产服务已原子写入返利到账状态并增加订单版本，多级结算流程原先又使用旧版本回写，触发冲突后导致整笔事务回滚。新增回归测试先复现旧逻辑失败，再将末尾状态回写限定为冻结分支；直接入账保留资产服务的到账状态。

退款记录原先未保留分账角色，会统一落为 SELF，与同订单消费者退款撞上角色唯一约束。退款记录改为继承原记录角色，历史 NULL 角色按 SELF 处理；冻结提成退款及已提现提成产生欠款两个场景均检查角色与原返利编号。真实数据库验收同时检查消费者和驿站的退款记录可并存。

# AI 能力中心 vNext 部署与运营说明

首发覆盖管理后台和后端。会员端继续沿用已有角色与会话入口，新建的五个角色默认不向会员开放。AI 能力中心不拥有资金结算、订单归因或 Token 主账本；现有 CPS 资产状态机、幂等和审计继续作为最终业务边界。

## 数据库与发布顺序

1. 备份并记录当前数据库迁移位置。在测试库执行尚未执行的 `backend/sql/module/ai-update.sql` 和 `cps-update.sql` 增量块，再部署应用。文件内 `ALTER TABLE ... ADD COLUMN` 是一次性迁移，不应重放整个更新文件。
2. 新库参考 `ai-all.sql`、`cps-all-in-one.sql` 基线；它们包含历史表结构、示例数据及 `DROP TABLE`，不能用于升级已有库。运行菜单种子前必须已创建 `system_menu`。
3. 确认六张能力管理表、`ai_tool_confirmation`、`ai_chat_role_version`、角色扩展字段、会话快照字段及 `source_conversation_id` 已创建；`cps_mcp_access_log` 应包含角色、Skill 版本、策略结果和拒绝原因六个新增字段。
4. 保持 `ai.capability-center.v2=false` 部署。菜单种子按组件和权限去重，使用数据库生成的主键；给运营账号分配查询权限，给发布人员分配维护权限。菜单创建不会自动授予所有账号访问权。
5. 在测试环境开启 `ai.capability-center.v2=true`，验收后再对选定后台实例灰度。此开关控制新会话捕获能力快照，现有快照会话仍按已保存的能力边界执行。

增量脚本默认只为租户 1 创建五个系统预设、初始 Skill 和 MCP 登记。其他租户必须独立配置自己的记录与授权，不能跨租户复用数据库编号。外部 MCP 客户端不再读取 YAML 或 Java 静态连接配置，统一由管理后台登记并从数据库加载；旧角色字段和无快照会话仍保留兼容，旧会话不自动生成或补写能力快照。

## MCP 注册与授权

在管理后台“AI 能力中心 / MCP 管理”中新增、测试、同步和启停 MCP 服务。新登记默认停用，应先测试连接、同步工具、审核风险与授权策略，再显式启用。海纳种子登记同样默认为停用，使用 `STREAMABLE_HTTP` 和 `API_KEY`（`X-API-Key` 请求头）认证，数据库只保存 `env:AI_MCP_TENANT_1_HAINA_API_KEY` 引用。通过部署环境设置对应变量；首版只支持 `NONE`、`BEARER` 和 `API_KEY` 认证，以及 SSE 和 STREAMABLE_HTTP，不支持 STDIO、执行命令或上传代码。Endpoint 不能包含用户名、密码、查询参数或 fragment。

本地 CPS 默认登记为停用，地址为 `http://127.0.0.1:48080/mcp/cps`，应与当前部署的 MCP 协议和端口核对。签名身份只会发送到 `LOCAL` 且编码为 `cps` 的回环服务；沿用已有 MCP 身份签名配置，未配置签名或缺少可信会员身份时拒绝执行。远程服务不接收本地可信身份上下文。

同步只发现工具元数据。新发现工具默认停用、风险为 `ADMIN`；运营人员必须逐项评估风险并启用。已有工具再次同步保留审核后的风险与启停状态，消失的工具标记为 `MISSING` 并停用。服务授权不能代替工具白名单。初始 MCP 策略没有工具白名单，所以迁移不会自动开放远程工具。

使用 `ai:mcp:query` 查询服务、工具、策略和审计，使用 `ai:mcp:manage` 注册服务、同步、调整工具风险及保存策略。`/admin-api/ai/mcp/log/page` 与 `/log/stats` 按当前租户读取真实审计表，仅返回安全字段，不提供原始请求、响应或密钥。统计中的 `ALLOW` 和 `CONFIRM_REQUIRED` 不计为已完成调用。

## Skill 与角色发布

Skill 版本按 `DRAFT → REVIEWING → PUBLISHED → ARCHIVED` 管理。修改草稿或绑定时带上 `expectedRevision`，版本冲突必须重新获取。已发布版本不可原地编辑；创建新版本后重新审核和发布。回滚切换到已有已发布版本，只影响之后创建的会话。

使用 `ai:skill:query` 查询，使用 `ai:skill:manage` 编辑、审核、发布、回滚和测试。绑定包括本地工具、MCP 工具和知识库。发布前校验工具、风险、服务及授权；写操作需要确认策略。测试接口默认返回 `READ_ONLY_PREVIEW`，展示提示词、输入、输出模板和只读绑定。显式选择执行并提交 `executeModel=true` 后，返回 `READ_ONLY_EXECUTION` 和模型输出；按所选或默认模型运行，只允许已登记且当前启用的只读工具，最多调用八次。沙箱不绑定会员身份，不开放写操作；MCP 工具还必须通过 Skill 白名单。真实执行会使用已配置模型并产生相应调用费用。

五个角色分别用于流量主选品、商家投放、消费者返利查询、视频号带货和抖音号带货。系统提示词和输出模板提供不同场景指导；实际可用的平台、商品和佣金仍由工具与平台接入情况决定，不能编造实时信息。

每次保存角色会在同一事务中追加 `ai_chat_role_version` 定义快照。更新时锁定当前角色行、校验请求中的当前版本并递增版本，数据库唯一键防止重复修订。历史接口 `/admin-api/ai/chat-role/version/list?roleId=...` 返回最近 100 次保存记录，要求 `ai:chat-role:query`，私有角色还必须属于当前用户。迁移只记录当时已有的定义，不能重建迁移之前不存在的版本记录；初始快照保留历史 CSV 绑定字段格式，之后保存的快照使用数组。历史保存提示词和能力编号，不复制模型密钥或 MCP 密钥。

创建会话时固定角色版本、已发布 Skill 版本、工具白名单、知识库和策略。角色或 Skill 更新不会给历史会话新增能力。修改 MCP 连接配置或工具 Schema 后，原会话对应能力可能被拒绝，需要创建新会话。切换角色通过创建关联新会话完成，`source_conversation_id` 仅记录来源，不复制会员身份或原能力。

后台普通会话没有可信会员绑定时，订单、返利、转链和资产操作应拒绝执行。需要会员身份的后台验证使用现有、受权限保护的 MCP 自测绑定入口；聊天文本或普通会话请求不能提供会员身份。高风险确认记录有有效期，绑定租户、会话和所有者，只能消费一次。超时或失败后先核对业务幂等记录和资产状态，不直接重复提交资金操作。

## 验收、观测与回退

- 覆盖服务不可用、认证失败、工具缺失和分页循环，确认故障仅隔离对应服务。
- 发布一个只读 Skill，创建选品角色会话；修改和回滚 Skill 后，验证旧会话快照不变、新会话使用新的当前版本。
- 验证伪造会员编号、跨租户查询、无权限工具、重复确认及过期确认均不能执行操作。
- 验证审计中记录角色、Skill 版本和策略结果，且密钥、签名和完整参数不进入新增日志接口。
- 灰度观测成功/失败数、平均延迟、P95、拒绝数，以及按角色/Skill 聚合的调用次数；告警阈值需结合实际监控平台配置。不能将单元测试通过视为真实 MCP 联通或生产验收。

回退时先关闭 `ai.capability-center.v2`，停止创建新的快照会话，并保留新表和审计记录。既有快照会话仍按快照安全边界执行；如需立即隔离故障 MCP 服务，在管理后台停用该服务。旧版本应用发布回退前，确认其不会忽略新会话安全边界；未经兼容验证不要让旧运行时处理新建的 v2 会话。数据库删除列或删除表不属于常规回退步骤。

本轮未执行生产迁移、外部 MCP 联调或全链路灰度。真实模型与 MCP 的网络联调仍需部署环境验证；通用工作流、代码插件及会员端角色选择不在本次范围内。

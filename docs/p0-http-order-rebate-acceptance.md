# P0：封闭 HTTP 登录及 CPS 订单返利端到端验收

基线：`develop@79c4b1d9154ebf10803c10018a3f1a45dfe0a143`。

## 已有证据，不重复认定为线上验收
- GitHub Actions 的 MySQL 8 Mapper、一致性、既有安全回归、构建及 UTF-8 均在该基线成功。
- MySQL 8 合成数据备份恢复不等于腾讯云备份原件恢复；生产部署仍指向旧版本。
- 现有 CI 中的令牌签发、日志外部 API、支付渠道等存在模拟依赖，不能推定真实 HTTP 登录或联盟回传可用。

## P0 阶段与通过标准

### 1. 封闭 HTTP 登录
在一次性隔离 MySQL 8 + Redis + Java 环境启动与生产一致的 HTTP 路由，仅回环网络；使用合成账号与配置。覆盖正确密码、错误密码、禁用账号、跨租户登录、过期/撤销 Token、无权限访问、退出后 Token 复用。验证 HTTP 状态、业务返回码、持久化副作用。确保没有真实短信或 OAuth 请求。

### 2. CPS 回调与订单归属
为单个联盟适配器提供合成签名、模拟订单、回调请求。验证签名拒绝、同一平台订单编号幂等、重复回调、乱序状态、跨租户伪造、佣金变动和并发消费。同平台不同租户的订单归属必须显式校验。不可用模拟渠道通过来声明真实联盟已接入。

### 3. 佣金、返利、退款、提现余额
使用真实生产 Mapper、租户拦截器、TypeHandler、MySQL 事务：订单创建→佣金确认→返利入账→部分/全额退款冲正→可提现余额核对。并发重放与异常注入后，校验账本业务唯一键、钱包归属、状态机单向转换、分单位整数精度、负余额保护和整体回滚。提现仅模拟，不进行真实资金划拨。

### 4. 迁移、启动与回退
在全新隔离库重建腾讯云 **151 表等价基线**（必须先核对实际结构和迁移前置条件），应用营销/支付 37 表、租户字段和 member v2.0.1 变更；验证重复执行、失败中断、索引/生成列、历史数据保留。DDL 不能假设事务回滚；只编写审批后可用的封闭发布和回退步骤。不能直接修改腾讯云 `cps` 业务库或线上 JAR。

### 5. 交付证据与门禁
每个阶段提交源码 SHA、CI 运行链接、测试数量/跳过数、真实依赖与 Mock 划界、异常报告。上线前另验收：真实备份只读副本异机恢复和离机取回、预置后台账号处置、第三方密钥轮换、受控封闭 HTTP 登录和新 JAR 灰度。

## 不可越过的边界
不得修改惠普电脑、其他生产系统、腾讯云现有业务库、备份原件、线上容器/JAR；不得开放公网、调用真实支付或提现。未获明确独立授权，所有上线/资金门禁保持 **NO-GO**。
